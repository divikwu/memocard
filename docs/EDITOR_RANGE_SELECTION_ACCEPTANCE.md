# 左侧拖动块范围选择

日期：2026-10-08。对应用户提供的 Codex 待办选区截图。

## 改动

此前的鼠标入口只覆盖编辑器内的空白和手柄左侧 28px 区域，用户从页面更靠左的空白处起手时不会触发。复现后改为监听页面指针起点，并将范围限定在正文所在滚动面板、正文高度内的左侧空白；正文文字和手柄保留原有行为。

- 不再依赖一条窄的隐藏拖选区域。按住鼠标后捕获指针，移入正文或移出编辑器也能继续扩选；侧栏、工具按钮和正文文字不会被拦截。顶部空白的扩展见下文。
- 支持正向、反向和缩选；同一待办列表选择单独的待办项。跨嵌套容器时提升为共同父级下的完整块，避免拆开结构。
- 复用现有 `BlockRangeSelection`、选区高亮、批量操作及撤销。拖选本身不更改正文，也不触发保存。
- 在可滚动祖先的边缘继续扩选；释放鼠标后停止滚动。Esc、指针取消或窗口失焦恢复拖选前的选区。
- 正文文字、按钮、中文组合输入和触摸起点不进入鼠标块拖选逻辑。

## 标题手柄单块拖动补充验收

用户报告拖一个标题却高亮全部内容。原因是标题手柄沿用了章节移动的默认范围：标题下方直到下一同级标题的块会自动加入移动对象。现在普通手柄拖动复用明确的块选择，未多选时只移动当前标题；Option/Alt 拖动才扩展到整个章节，手柄提示同步说明。已明确选中的多块继续一起移动，菜单的章节移动和列表项的 Option/Alt 整表移动保留。

- 新增单标题回归测试，修复前拖动载荷包含标题、待办和末尾段落，修复后只包含标题，落到文末时只移动标题，一次撤销恢复原文。新增明确选择标题及一段正文后拖动的测试，保证不带上未选中的后续块。
- `pnpm verify` 通过：全部 UI 351 项测试；章节拖动的既有测试改为显式按住 Option/Alt。原有 lint 和构建体积警告保留。

- 显式选择 `H2, UL` 后拖动仅携带这两个块，落到末尾后为 `P, H2, UL`，撤销还原。Option/Alt 拖动时明确选中 `H2, UL, P`，落在原章节内部不改变正文。浏览器无错误日志。
