# 本机 Web

本机 Web 是 Mac 应用的另一个界面入口。React 界面、编辑器与主题配置和原生应用共用；笔记、图片、草稿仍通过同一个 Swift 核心读取和保存。没有浏览器专用笔记库，没有新增 Node 写入服务，也没有扩大 MCP 的只读权限。

## 使用

1. 构建并运行 Mac 应用，选择已授权的 MemoCard 笔记文件夹。
2. 在设置中点击“在浏览器中打开”，应用启动本机服务并打开默认浏览器。
3. 在浏览器中查看、新建、编辑、搜索笔记，添加标签和图片，保存或恢复本机草稿。
4. Mac 应用保持运行。可以在 Mac 设置中“关闭本机 Web”，MCP 不受此操作影响。

需要在 Codex 内置浏览器或其他浏览器中使用时，点击“复制访问链接”，在 2 分钟内将链接粘贴到目标浏览器。链接只能兑换一次，重新复制会撤销尚未使用的旧链接；已建立的会话继续有效。

另有 [独立 Web](BROWSER_VAULT.md)：`http://127.0.0.1:5179/` 由 Vite 提供，受支持浏览器可直接授权文件夹，不依赖 Mac。此文档仅描述 Mac 提供的鉴权本机 Web 模式。本机网页和资源由应用提供，端口由系统动态分配，不需要 Vite 或另一个终端服务。

该地址只适用于这台 Mac，不是局域网、互联网或独立 iPhone Web 客户端。iPhone 继续使用原生客户端。iCloud Drive 同步仍由系统负责；浏览器保存成功仅表示本机文件提交成功。

## 权限与接口

- 服务只监听 `127.0.0.1`，校验精确 Host 和写请求 Origin，不允许 CORS。
- 启动链接在 URL fragment 中携带一次性、短时授权；前端立即移除 fragment 中的凭据，通过同源 POST 换取 HttpOnly、SameSite=Strict 会话 Cookie。不要分享启动链接。令牌不写日志、笔记库或仓库。
- 网页直接加载打包的 HTML/CSS/JavaScript/字体；HTTP 页面应用独立 CSP，只允许同源数据与图片，禁止原始 Markdown HTML 执行、嵌套页面和表单提交。
- `POST /api/bridge` 复用版本 1 的结构化请求与响应，仅放行状态、笔记查询/读取、标签、草稿、保存和附件导入。图片通过浏览器文件选择器选择，再传给 Swift 导入。
- `GET /api/assets/assets/...` 需要会话授权，只提供受支持的图片；Swift 再次核对路径、授权和文件可用性，不提供任意文件读取接口。
- 文件夹选择、创建与切换以及 MCP/Web 的启停在 Mac 应用中完成。网页不能唤起原生目录选择器或更改 MCP 配置。
- 切换笔记库、关闭 Web 或退出应用时，监听和会话被撤销。请求绑定启动时的笔记库和授权代次，旧页面不能向新选择的笔记库写入。

## 保存与断开

正文仍使用原始 Markdown，并带读取时的 `baseHash` 保存。Mac、外部编辑器和浏览器并行修改时，Swift 拒绝过期覆盖，保留草稿并报告冲突。

网页可见时定时刷新；返回页面和手动刷新也会重新核对。用户加载更多笔记后，后台检查连接和库状态，避免自动把列表重置到第一页；查看最新列表可手动刷新。

连接断开时不能新建笔记；当前编辑内容保留在页面内，保存失败不会关闭编辑器或清空输入。尚未成功保存到 Swift 草稿的输入，在离开页面前使用浏览器标准提示保护。**这不保证浏览器崩溃或强制退出后恢复未提交输入**。应用重启会使用新的端口和授权，请从 Mac 应用重新打开；旧页未保存内容应先复制出来。

网页外观保存在浏览器当前 origin，与原生 WKWebView 独立；动态端口变化后可能回到默认主题。该限制不影响已提交的 Markdown、图片和 Swift 草稿。

## 验证

自动化入口：`pnpm test:local-web`、`pnpm --filter @memocard/ui test`、`pnpm verify`。

本轮已在真实 Mac 应用与 Codex 内置浏览器间完成带图新建、编辑、搜索和文件核对，详见 [实施状态](IMPLEMENTATION_STATUS.md)。关闭/重启与拒绝越权请求由真实 Network.framework 自动化测试覆盖；断开时保留编辑内容由界面测试覆盖。没有为了测试中断用户正在试用的 Web 会话。本机 Web 验收不替代真实 iPhone 安装、iCloud 双端同步及完整 M0–M5 交付。
