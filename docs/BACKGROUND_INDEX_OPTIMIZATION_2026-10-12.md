## 实现与保存语义

- 原生 `VaultStore` 首次索引改为协作式分批处理。UI 请求后台模式后立即取得读取进度，首批可安全识别的笔记提前显示；后续完成全库源校验，再后台补齐搜索/筛选所需的派生缓存。每批最多 32 项，约 12 毫秒后让出执行机会。
- UI 区分“正在读取笔记库”和“正在整理搜索和筛选”。读取阶段显示已读取数量，不虚构未知总量或百分比；派生阶段显示已整理/总数。首次没有结果时显示载入状态；进度轮询不重置编辑器，也不禁用正文。
- 首次源校验期间，输入立即进入独立本机恢复记录；源提交返回暂缓信号，释放编辑器保存队列，避免较新的草稿被一个长请求阻塞。前端自动重试，校验结束后提交最新正文和待保存属性。属性读取也自动重试，避免长请求超时。
- 源写入仍要求完整覆盖、无重复身份、当前文件哈希匹配，并保留协调写入与事务恢复。校验尚未结束时不能把本机草稿称为源文件保存成功；派生索引阶段可以正常提交源文件。
- 兼容库首批对外显示的身份先持久化，避免读取中途关闭后草稿失去对应笔记。后续身份按原有路径/哈希规则统一收敛，避免每个批次重写全库身份表。关闭或切库取消后台任务和旧库待提交请求。
- 派生索引每批读取当前缓存版本；索引中发生源保存会重新补齐失效项。普通空查询避免无意义地拼接与搜索所有正文。

此改动主要适用于原生宿主和本机 HTTP 服务共用的 `VaultStore`。独立浏览器直接授权目录的存储实现没有在本轮迁移到这套后台索引。

## 性能证据

同一 Apple M4 / 16 GB / 本地 APFS，Release 核心，独立合成库，每篇正文 2,000 字节。编译和测试结束后单独测量。每种规模/格式单次运行；没有清除系统文件缓存，因此是首次 Store 索引，不能称为物理磁盘冷启动，也不是跨运行 P95。

优化前同样规模的格式 2 库，首次 `getStatus` / 随后 `queryNotes` 分别为：千篇 942.5 / 351.9 毫秒，万篇 9,466.3 / 3,609.1 毫秒。它们串行完成后才能取得列表。新实现首篇可编辑的原生请求链路如下，不能等同于浏览器首屏渲染时间：

| 库 | 首篇可编辑 | 草稿写入 | 首次源提交 | 完整索引 | 状态/读取请求 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 千篇 · 格式 2 | 42.6 ms | 2.03 ms | 1.47 s | 2.06 s | 28.9 / 20.6 ms |
| 万篇 · 格式 2 | 49.0 ms | 2.11 ms | 12.89 s | 23.80 s | 91.3 / 100.2 ms |
| 万篇 · 格式 1 | 33.2 ms | 2.19 ms | 19.11 s | 30.49 s | 98.8 / 103.8 ms |

此表在索引过程中每 100 毫秒主动请求状态和单条读取，并提交正文及属性；读取样本分别为 17 / 146 / 162。P95 只描述该单次运行的请求样本。高频探测与协作让出会增加总耗时，因此本轮提升的是首次可用性和后台响应，不能据此声称完整索引比原同步流程更快。三组源提交均发生于派生索引阶段；磁盘响应哈希、重开后的正文/属性一致，其余 999 / 9,999 / 9,999 个源文件字节不变。

每 1 秒探测状态和单条读取的补测仍进行正文及属性提交：千篇首篇可编辑 39.5 ms、源提交 1.33 s、完整索引检测时间 2.10 s；万篇分别为 49.6 ms、12.92 s、19.47 s。完整索引检测有约 1 秒粒度。万篇 18 个读取样本的状态/读取 P95 为 130.1 / 118.5 ms；样本数较少，不能推断稳定分布。这组也未证明总耗时下降，确认的是提前可编辑、草稿独立落盘，以及后台任务与源保存正确共存。

## 真实界面与一致性验收

使用生产 UI、生产本机 HTTP 服务和生产 `VaultStore`，连接单独生成的万篇格式 2 库。没有读写用户当前真实库。

1. 首次打开显示读取进度；打开首批笔记后连续输入，读取进度更新没有替换或禁用正文。
2. 重开索引并在读取阶段编辑：同一次探测确认 UI 仍处于读取、本机草稿包含新输入、源 Markdown 尚无该输入；随后继续输入最新内容。
3. 校验完成后正文自动提交。连续修改 summary 和正文，编辑器仍可用，无错误提示。
4. 关闭并重新打开 Store、重载 UI，已提交的最新正文和 summary 保留，正文可编辑且无错误提示。关闭 UI/服务后另建原生 Store，磁盘 SHA-256 与响应哈希相等，全部 7 个编辑标记和 summary 正确，其余 9,999 文件字节完全不变，活跃待恢复内容为零。现有协议保留 1 份空恢复记录，UI 不将其视为恢复内容；验收脚本按该语义判定。

## 保留边界

- 初次未知身份的兼容库先提供一小批已持久化的预览，完整身份校验后才显示其余内容。搜索、快捷筛选与计数在后台阶段可能不完整，UI 明示这一点。
- 属性定义依赖全库校验；读取阶段先允许正文编辑，属性面板完成校验后可用。未被首批读取的深链笔记仍可能等待校验，不宣称任意笔记都能在几十毫秒内打开。
- 12 毫秒是批次让出目标，单个协调文件读取、解析、最终排序及身份持久化仍可能超过该时间，不能作为硬实时上限。
- 云端待下载、文件提供商长时间阻塞、网络卷以及超过万篇的规模没有完成本轮真实性能验收。非本地 APFS 后续操作仍采用保守扫描路径。
- 用户明确没有第二设备，双设备 iCloud 同步继续记录为未验证；本机索引完成不表示云端上传或其他设备接收完成。断电、磁盘满和真实中文 IME 长时间输入亦不因本轮通过而变为已验证。
