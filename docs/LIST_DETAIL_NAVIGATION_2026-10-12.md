# 列表到详情的即时加载反馈

日期：2026-10-12。仅在当前工作区修改、构建和验收；未提交、安装或发布，未重启用户当前服务，也没有修改真实笔记库。

## 问题与行为

原列表点击先等待 `getNote`，成功后才更换地址和挂载详情。请求等待期间只有操作禁用，列表留在原地；既有详情占位仅覆盖直接链接路径。

现在列表点击立即更新笔记地址并显示详情布局和加载占位。读取最新正文之后才挂载可编辑组件；不使用列表中的旧正文或旧哈希提前编辑。编辑器仍可按原规则恢复唯一匹配的本机草稿，并保留草稿自身的 baseHash。读取失败但有可恢复草稿时，保留既有离线恢复路径和后续源冲突校验。

- 加载期间可以返回，桌面和移动端均有返回入口。取消打开会使旧请求失效；迟到成功或失败不能重新打开详情，也不能覆盖新笔记的输入。
- 返回恢复列表原滚动位置，并将焦点还给原卡片；已经卸载的卡片通过笔记 ID 在新列表中重新定位。
- 无草稿的读取失败留在详情上下文，显示错误和返回；可重试错误的「重试」只重新读取同一篇笔记，不重新加载整个列表。
- 直接链接和 hash 切换使用相同失败语义。路由结束不会提前清除失败详情，避免退回列表却保留详情地址。
- 已进入编辑器后的切换/返回仍先执行现有保存队列；保存失败或冲突时保留编辑器和输入。

生产代码仅改 `apps/ui/src/App.tsx`，复用既有 pendingRoute、请求代次、LoadingNote 和保存逻辑，没有新增保存接口或修改原生存储、索引、草稿协议。

## 回归

新增 9 项 App 回归，覆盖：

1. 点击当次渲染即显示详情占位，读取之前不存在编辑输入和草稿写入；最新读取的正文/哈希用于后续保存。
2. 加载中返回后旧读取成功/失败两种情况，列表可再次打开，滚动位置及焦点恢复，不产生源保存。
3. 返回后打开第二篇，旧响应迟到也不能覆盖第二篇未提交输入。
4. 浏览器返回取消读取，随后响应不能重新打开详情。
5. 读取失败显示详情错误，重试同一篇取得最新正文，不刷新列表。
6. 延迟恢复草稿使用原 baseHash，源冲突后仍保留草稿、输入与详情地址。
7. 加载中连续 hash 导航，旧失败不影响新请求的占位及正文。
8. 失败详情返回后错误清除，列表不被禁用，不产生源保存。

其中返回迟到结果的两种情况分别计为一项。前 7 项场景在旧实现全部失败后修复；补充 2 项覆盖连续 hash 和失败返回。另加强既有直接链接失败测试，先确认它会丢失详情上下文，再修复路由清理；适配既有恢复入口测试，在详情加载中先返回再恢复，没有删除其迟到失败和草稿保护断言。

## 生产 UI 验收

使用最新生产 UI 构建，配隔离的本机合成接口，并在内置浏览器后台新建验收标签页。接口可指定延迟/失败；不连接真实 Vault，也不将该接口当作原生文件系统一致性证据。草稿、哈希和保存冲突由真实 App/Editor 组件回归以及未修改的原生测试验证。

1. 将单条读取延迟 10 秒：点击后立即进入详情地址，显示骨架及返回按钮，列表和正文编辑器未显示。
2. 读取中返回：立即显示列表，焦点回到原卡片。随后打开另一篇，显示它读取后的最新正文。
3. 读取失败及直接链接重载失败：详情显示「无法打开笔记」、源读取错误、重试与返回；重试后正文编辑器显示最新正文。
4. 没有在界面验收中输入或提交真实内容。验收请求日志记录于证据目录，测试标签页和合成接口在完成后关闭。
