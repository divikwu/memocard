## 写入保护

- 删除使用最新 `get_note` 的完整 binding 和 contentHash；恢复使用最新 `get_trashed_note` 的顶层 binding 和 note.contentHash。
- 适配器、原生 TCP listener 和服务宿主均校验库与实例。切库、同库重启和停用后的旧绑定不能继续写入。
- 旧正文或归档版本拒绝提交。恢复遇到活动 ID 重复时保留两侧内容；同名文件使用新文件名，不覆盖占位文件。
- 恢复将已审核的 Markdown 字节发布为可见活动文件，再移除归档，避免沿用文件提供者的归档隐藏元数据。事务日志在移除归档失败时回滚发布文件，跳过对已处于原状态的文件重复写入。

## 本机端到端验收

通过 Codex 已配置的编译后 stdio 入口连接已安装的独立 MemoCardService，目标为 Mindspace。主客户端保持退出。

1. 仅新建临时笔记，写入后更新，确认旧内容 hash 不能删除。
2. 移入回收站，读取精确归档并核对 ID、正文与 hash，确认活动笔记缺席、当前 binding 未变化；旧归档 hash 不能恢复。
3. 真实退出并重新启动服务进程，确认 PID 已变化。核对所选库原目录 bookmark 身份保持一致，实例已更换。
4. 旧实例的删除与恢复请求均被拒绝。重新读取归档后恢复，并立即通过原 ID 读回，正文与 hash 保持一致。
5. 对恢复后的笔记继续修改，读回正文和回执版本一致；随后将该临时笔记再次移入回收站。
6. 最终核对原有 8 篇活动笔记的 ID、标题、路径和内容 hash，以及原有 5 条回收记录的键和 hash，均未改变。本轮正式验收和排查使用的两篇临时记录均已归档。
