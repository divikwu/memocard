# 完整后台索引耗时优化

日期：2026-10-12。承接[首次打开与后台索引](BACKGROUND_INDEX_OPTIMIZATION_2026-10-12.md)，仅在当前工作区优化、测试和构建；不安装、不发布。本轮基线包含此前所有未提交修复，并非单独的 HEAD 提交。

## 瓶颈定位与改动

先保存本轮前完整补丁及可执行程序，再用 macOS `sample` 分别采样读取和派生索引阶段。

- 派生阶段：`buildBackgroundFilters → noteQuickFilters` 的纯文本预检查进入 Swift 字符串正则和 Unicode 大小写折叠路径，每篇反复执行。改为 ASCII 标记字节检查，加预编译的 Foundation URL 标记正则；遇到候选标记后仍走原有完整 Markdown 语法处理。
- 读取阶段：`advanceScan → coordinateRead → inlineTags` 在正文包含重复标签时，先反复验证相同标签、最后才去重。将去重提前到规范化之后，并复用不可变的匹配表达式，保持首次出现顺序与原有有效性规则。

生产改动限于 `NoteFilters.swift` 与 `Obsidian.swift` 两个热点。没有降低全库校验范围、删除文件读取、放松哈希或重复身份检查；没有改动批次让出、编辑保存队列、草稿隔离和事务恢复。

## 性能对照方法

Apple M4 / 16 GB，本地 APFS，Release 原生核心。基线从本轮前补丁重建，与优化版使用完全相同的 harness；分别生成独立的千篇、万篇格式 2 Markdown 库。每轮先写入合成文件再首次打开 Store，未清除系统文件缓存，所以不能称为物理磁盘冷启动。

主对照正文为每篇 2,000 字节、40 次重复标签。优化前后交替运行三轮，顺序为前/后、后/前、前/后；表格报告三次中位数。每 250 ms 请求状态、单条读取并分别更新两个客户端的独立草稿；首次源校验期间还排队提交正文，随后更新属性。完整索引耗时计至检测到读取及派生索引都完成，存在约 250 ms 探测粒度。

额外各做一次混合语法对照和 100 ms 高频请求对照。混合正文包括普通文本、链接、引用图片、代码块和 Unicode 多标签；详见结果中的正文长度范围。额外对照是单次结果，不能当作稳定分布。

## 回归与一致性

新增 3 项原生回归：

1. 长 Unicode 正文、大小写 URL 标记与完整 Markdown 快捷筛选语义，包括注释、代码、引用定义、图片及现有 `httpſ` 边界行为。
2. 重复标签的规范化、数字标签排除、首次出现顺序，以及代码区域排除；保留现有组合字符解析结果，不借性能优化改变语法。
3. 8 个并发读取任务各执行 50 轮，验证共享不可变表达式没有交叉污染。

保留并通过现有后台索引回归：首次读取期间草稿可继续保存、源提交暂缓；派生索引中多轮正文/属性保存；关闭和切库取消；兼容身份持久化；外部改动与重复身份仍阻止不安全源写入。

性能 harness 每组还断言：磁盘 SHA-256 等于保存响应、重开后正文和属性一致、派生链接筛选能找到索引期间的编辑结果、两个客户端最后一版未提交草稿分别恢复、其余 999 / 9,999 个 Markdown 文件字节不变。独立未提交草稿允许保留旧 baseHash，不误称为已提交内容。

本机[证据目录](../verification-artifacts/full-index-2026-10-12/README.md)包含本轮前补丁、两个阶段采样、同脚本基线/优化版、原始 JSON、对照汇总和完整验证日志，被 Git 忽略。全部性能库为临时合成数据，没有修改用户真实笔记库。

本轮未修改 UI、保存协议或后台索引架构；此前已验证的真实 UI 连续编辑流程见前一份报告。完整索引仍需全量协调读取和身份校验，最终排序与身份持久化仍可能阻塞单次请求，12 ms 批次目标不是硬实时上限。云端待下载、网络卷、物理冷磁盘、超过万篇规模及 iCloud 双设备同步未验证；用户当前无第二台设备。所有结论限于上述工作负载和本机环境。
