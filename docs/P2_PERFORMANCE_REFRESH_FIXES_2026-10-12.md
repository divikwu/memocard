# MemoCard 剩余 P2：大库性能与分页刷新

日期：2026-10-12。范围：原审查报告 F07、F08。基于前两轮未提交修复继续，保留已有改动。未安装、未发布、未提交、未合并；没有修改用户实际笔记库。所有故障、性能和浏览器验证使用独立合成库。

## 修复内容

### F07 · 已核验的本地索引与首次扫描成本

原先单条读取、正文保存和属性修改都重新枚举目录，即使 Markdown 已缓存也要重复执行完整路径/云状态检查。新增的本地 APFS 索引保存目录身份、目录条目和已解析笔记；每次重新使用索引前核验目录与所有已知源文件的设备号、inode、大小、mode、mtime 和 ctime（含纳秒）。修改的文件重新协调读取、哈希和解析；目录条目变化、目录替换、异常或不完整覆盖退回完整扫描。

没有按时间间隔盲用旧快照，也没有移除无关笔记损坏和重复 ID 的写入门槛。文件 presenter 的变更通知使批次快照失效，下一次操作仍核验本地索引。云文件、非本地 APFS、跨设备挂载下不启用该索引；源写前哈希、NSFileCoordinator、冲突检查、恢复事务和草稿隔离继续保留。

首次扫描的优化包括复用带锁的 ISO 时间格式器、用 POSIX 文件类型/真实路径检查替代重复的 Foundation 元数据展开，以及对不可能包含图片或链接的普通正文跳过完整 Markdown 筛选流程。时间格式与日期有效性规则、符号链接和路径边界检查没有放宽。

**复杂度边界：** 热态操作仍逐条核验文件元数据，兼容模式的身份事务仍可能序列化全库身份，均不是 O(1)。本次消除的是稳定目录反复枚举和重复解析带来的主要延迟。首次索引仍同步执行；更大库、复杂 Markdown 与慢云目录仍需要单独测量和后续后台索引设计。

### F08 · 保留已加载页数，更新外部变更

移除加载更多后的提前退出。后台轮询、重新聚焦、回到可见状态和原生变更事件都刷新正文列表、草稿、异常、标签、目录和筛选计数。

刷新从第一页开始，沿新的游标链重读已加载的页数，全部成功后一次替换列表与下一页游标。列表刷新期间保留旧内容；仅「加载更多」暂时等待刷新完成，防止两个快照的游标链交错。不会整页禁用或覆盖编辑器内尚未提交的内容。

游标失效时最多重读三次；持续外部改动时保留现有列表并提示，恢复后清除提示，不误报服务断开。「加载更多」拿到旧游标时先刷新当前范围，再允许继续加载。分页/刷新期间收到的原生事件延后执行。保留首个可见笔记相对视口的位置；若该笔记被删除或移出筛选，不保证其锚点仍存在。

保留的是已加载的页数和阅读位置，外部新增、删除或重新排序后，末尾成员可能相应变化。刷新成本随已加载页数增长；未新增无限列表虚拟化或服务器长驻分页会话。

## 回归和一致性

- 新增 3 项原生回归：稳定目录连续正文/属性编辑不重复枚举（含原生 presenter 失效通知）、无关文件损坏/重复 ID 阻止写入、嵌套目录新增/移动/删除保持身份与其他源字节。
- 扩展原分页测试并新增游标重试、持续变更、加载更多恢复、延后原生通知、滚动锚点、刷新/分页串行回归；本机 Web 和浏览器文件模式共用的 App 流程均覆盖。原先要求「不再查询」的断言改为要求新页内容更新且页数保持。
- 已有回归继续覆盖同尺寸且恢复 mtime 的外部改写、原子替换、符号链接、重复身份、不完整读取、过期哈希、丢失源文件、全库属性转换及恢复事务故障。
- 隔离真实浏览器：95 篇初始库，加载两页 60 条后外部修改一条正文和两项属性、删除一条、新增两条与一份草稿。轮询自动更新后仍为 60 条，记录的可见锚点偏移 0 px；继续加载最终 96 条/96 个唯一 ID，全部与磁盘身份记录匹配。重开笔记的正文、summary、verified 与源文件一致；93 份未参与变更的原文件逐字节一致。
