# Notion 块间距与编辑状态核对

2026-09-30。针对块间留白仍可落入光标的问题，只读检查用户打开的 Notion 参考页、官方文档和本地编辑器代码。本轮为研究，不代表交互重构已经实现。

## 已确认的证据

- Notion 参考页的正文分别位于 `notion-text-block`、`notion-bulleted_list-block` 等有 `data-block-id` 的容器中；内部有可编辑文本节点。页面末尾真正的空文本块同样有块容器、文本节点和最小高度。布局留白与空文本块不是同一对象。
- 当前参考页文本节点的纵向 padding 为 2px，文本行高为 21px。这是该页面的测量值，不作为 MemoCard 的固定排版参数，也不能据此推断 Notion 私有源码。
- 官方说明区分块内换行（Shift+Enter）和插入文本行（Enter）；Esc、方向键和 Shift 选择也有独立的块选择语义。真实空文本块可以作为内容被移动。
- MemoCard 当前使用连续 Markdown 源码作为 CodeMirror 文档。普通 Enter 插入两个换行；间距由空行装饰承担。源码分隔行仍然属于浏览器及 CodeMirror 的选区，因此改行高、隐藏手柄不能阻止光标进入。
- 目前浅蓝色整块高亮是根据文字选区覆盖范围绘制的，不是独立的块选择模型。

## 正确的产品规则

| 对象 | 编辑行为 | 显示规则 |
| --- | --- | --- |
| 块间排版间距 | 无独立光标位置，无块手柄 | 来自 Typeset 元素关系与风格配置 |
| 用户创建的空文本块 | 可聚焦、输入、删除，具有块身份 | 正常输入行，不应因为正文为空就隐藏 |
| 块内软换行 | 属于当前块，可用文本光标编辑 | 使用正文行高 |
| Markdown 语法分隔符 | 保留在文件中，不作为独立编辑块 | 由编辑视图映射消化 |

原实现以“行为空”判断间距，无法可靠区分以上状态。不能把所有中间空行都禁止编辑，也不能仅把 caret 设为透明。

## 建议的修正路径与验收门槛

1. 在已有源码范围索引上区分语法分隔范围、内容块、编辑会话中的空文本块。先约定普通段落、列表边界及连续空行的映射；标准 Markdown 不能无歧义地保存 Notion 的全部空块语义，需要明确重新打开文件时的规则，不偷偷引入存储迁移。
2. 建立分隔范围的视图替换和光标映射验证。Typeset 只负责块容器的外部间距，不再靠可编辑空行制造间距。CodeMirror 的替换装饰或 atomic ranges 只是候选机制，不是已经验证可行的完整方案。
3. 同时处理点击定位、上下左右移动、跨块文字选择、Enter、Shift+Enter、Backspace、输入法、撤销与复制粘贴；不能只修方向键而让鼠标或输入法仍落入隐藏源码。
4. 手柄与选中背景都绑定实际块；排版间距不参与命中。真正的空文本块仍提供正常编辑和创建能力。
5. 保留 Markdown 主文件和未修改源码。先在测试库验证：段落到列表、列表到段落、连续 Enter、连续空行、嵌套列表、代码空行、跨段选择、移动后撤销，以及保存再打开。

通过条件：所有输入路径都不能把光标停在纯排版间距；用户主动创建的空文本块仍可用；源码和撤销历史不损坏。若 CodeMirror 方案无法同时满足这些条件，单列失败场景再评估编辑内核，不以继续增加 CSS 补丁宣称完成。

## 本轮实现进展

已增加源码分隔范围映射：顶层相邻块和同一列表内相邻项之间，第一条 Markdown 分隔空行通过替换装饰退出编辑布局；额外空行、首尾空行及代码块内部空行仍保留。间距由后一个元素的 Typeset 规则提供。折叠光标的事务过滤阻止选区落入分隔范围，非空跨段选择保持原始源码范围。

247 项 UI 测试通过，包括源码保留、额外空行、代码空行、跨段选择、合并与撤销。测试库页面确认分隔空行不再生成独立文本行，方向键从末段直接进入上一列表项，点击间距落入相邻文本。真实中文输入法组合过程仍需手工验收；这不是完整 Notion 块选择模型的实现。
