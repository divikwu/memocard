## 已确认问题

### 1. P2：迟到的笔记读取响应覆盖新建编辑器，丢失新输入

- 位置：`apps/ui/src/App.tsx:102-107`、`:160`、`:175`、`:261`。
- 触发：打开已有笔记时 `getNote` 尚未返回；用户点击仍可用的“新建笔记”，输入正文；在 650ms 草稿自动保存前，旧读取返回。
- 结果：旧响应直接 `setEditing`，带不同 key 的 Editor 替换新编辑器。卸载清除草稿定时器，没有发出 `saveDraft`，新输入丢失。
- 证据：独立 Vitest 用真实 App 和真实 Editor、可控延迟的原生响应复现；期望保留新内容的测试失败，实际变为旧笔记正文。
- 修复方向：对打开操作添加请求序号/取消检查；新建或切换编辑会话使旧请求失效；加载期间的入口必须与会话保护一致。

### 2. P2：只改正文也会改写合法标签

- 位置：`apps/ui/src/Editor.tsx:22`、`:94-95`、`:207-208`。
- 触发：外部 Markdown 含 `tags: ["machine learning", "C#,F#", "#literal"]`，进入应用后只编辑正文并保存。
- 结果：标签变为 `["machine", "learning", "C#", "F#", "literal"]`。空格、逗号和前导井号在往返转换中丢失；原生校验 `Models.swift:143-148` 接受原标签。
- 证据：独立 Editor 交互测试确认 `saveNote` 参数已改变标签，即使用户没有触碰标签输入。
- 修复方向：用独立标签项编辑并保存数组；至少未编辑标签时必须保留原始值。

### 3. P2：子目录笔记的附件相对路径错误

- 位置：`packages/native-core/Sources/MemoCardCore/VaultStore.swift:409-410`、`apps/ui/src/urls.ts:9-18`。
- 触发：外部把笔记移到 `notes/folder/moved.md`，再在应用中导入图片。
- 结果：仍插入 `../assets/<id>.png`，标准 Markdown 解析后指向不存在的 `notes/assets/`；改成正确的 `../../assets/` 又被前端拒绝。当前前端忽略笔记目录，可能掩盖写出的错误链接。
- 证据：隔离 Swift 包和合成库复现 `markdownTargetExists=false`、`actualAssetExists=true`；实际 `assetUrl('../../assets/image.png')` 返回 null。
- 修复方向：按当前笔记所在目录生成和解析相对引用，解析后再做笔记库边界与符号链接检查。

### 4. P2：图片选择/导入与展示支持的格式不一致

- 位置：`packages/native-core/Sources/MemoCardCore/VaultStore.swift:398-410`、`apps/ui/src/urls.ts:18`。
- 触发：原生选择器允许 `.image`；导入有效 TIFF。
- 结果：核心接受并保存 TIFF、返回图片引用，前端却将其显示为“仅显示笔记库中的图片”，因为扩展名允许列表不含 TIFF。
- 证据：隔离环境用 ImageIO 生成有效 2×2 TIFF，真实导入结果为 `../assets/<id>.tiff`，真实前端解析函数返回 null。
- 修复方向：统一选择器、导入验证与显示支持范围，或导入时转成已支持的格式。

### 5. P2：合法笔记集合可让默认 MCP 搜索断开连接

- 位置：`apps/apple/Sources/LocalReadServer.swift:79-80`、`packages/native-core/Sources/MemoCardCore/VaultStore.swift:229`、`:261-277`。
- 触发：10 条各 1 MiB 的合法笔记，使用默认搜索。当前分页仅限制条数，返回完整正文；本机 TCP 响应限制为 8 MiB。
- 结果：状态为完整覆盖、10 条笔记且无异常，默认搜索却报 `PROTOCOL_ERROR: Native connection ended before a complete reply`；设置 `limit:5` 或读取单条成功。
- 证据：临时独立测试链接真实 MemoCardCore、生产 LocalReadServer 和生产 Node requestNative 完整复现；没有写入正在使用的测试库。
- 修复方向：搜索返回有长度限制的摘要，或按响应字节预算分页；超限也应返回可识别错误，而不是直接关闭连接。

### 6. P2：MCP 抹平原生错误码，无法区分恢复方式

- 位置：`apps/mcp/src/native-client.ts:89-91`。
- 触发：原生返回游标过期、笔记不存在或鉴权失败。
- 结果：`STALE_CURSOR`、`NOTE_NOT_FOUND`、`UNAUTHORIZED` 都变成 `NATIVE_REJECTED`，客户端不能可靠决定重新分页、重新授权还是停止读取。
- 证据：独立官方 MCP SDK 调用与合成 TCP 主机复现三种错误被转换成相同错误码。
- 修复方向：可清理可能含文件名/正文的错误消息，但保留允许列表中的稳定错误码。

### 7. P3：MCP 日期上限说明与实际行为相反

- 位置：`apps/mcp/src/server.ts:27`；原生执行位置 `VaultStore.swift:257`。
- 触发：客户端根据 schema 中“包含结束时间”的说明设置 `to`。
- 结果：创建时间等于 `to` 的笔记实际被排除。原生行为符合计划的左闭右开区间，对外描述不正确。
- 证据：官方 SDK `listTools` 返回 inclusive 描述；原生日期测试和条件确认 exclusive 行为。
- 修复方向：将 schema 描述统一为结束时间不包含。
