默认 `src/main.tsx`、`pnpm build` 和 Apple/服务打包继续使用现有 UI；新版 Web/H5 从独立入口构建到 `dist-web-next`。运行命令及 CI 边界见 [ui-next.md](../../../ui-next.md)。

提交前完整检查发现编辑详情路由有约 1.9 KiB gzip 增量。为定位来源，在独立输出目录构建诊断版本：将 23 个旧入口模块虚拟恢复到固定提交 `b3620f08c4077961176d2ee89fdbf1a6dc25bf0b`，保持当前 App、Provider、基础组件、CSS 和构建配置。实际替换路径、九条路由结果及 CSS 哈希比较见 [记录](core-boundary-comparison.json)。

| 同 CSS 的入口对照 | raw 增量 | gzip 增量 |
| --- | ---: | ---: |
| 编辑详情 | 4,559 B | 1,894 B |
| 编辑详情与保留 Markdown | 4,675 B | 1,931 B |

这项诊断隔离的是提取共享逻辑前后的入口边界，也包含类名字串和分块差异；它不能证明每个字节都不可优化，也不构成旧版功能验收。未发现新的日期、图表或完整主题生成器被同步引入。

本轮同时减少无关加载：

- 按 Web 侧栏、H5 操作、原生框架和主页标签栏拆分样式；[31 条规则的选择器、媒体条件和声明保持一致](sidebar-css-declaration-parity.json)。
- 可选字体注册表在选择打包字体后加载，默认 Geist、系统字体和 SC 子集沿原路径；[146 个字体文件及 6,245,480 B 字体资源完全一致](font-assets-parity.json)。保持斜体注册、并发去重、失败后重试与现有字体 API。

最终仅为两个编辑详情路由分别登记 2 KiB gzip 的共享适配迁移成本。其余路由、首屏、raw 和字体预算在此次提交检查中未追加额度；此前 token 系统的预算变化仍在脚本注释中单独记录。保留大图首次打开等既有交互时序，没有为此新增等待界面。
