# 基础规范

## 原则

内容优先，延续当前低装饰的界面。共享语义、品牌资源和具有复用价值的基准；系统控件的内部布局由平台管理。新增规则先在真实组件上验证，再推广，避免为一次性数值建立全局 token。

## 颜色、主题与状态

Web 沿用 `background / foreground / muted / border / primary / sidebar-*` 等 CSS 语义。浅色、深色、跟随系统、强调色、中性色、圆角与字体的设置和本机存储格式保持不变。自定义原生侧栏消费同一份已解析 palette；系统文字、材质、确认框和菜单保留系统语义。

选中、悬停、按下、键盘焦点和禁用是不同状态：选中表达当前位置，焦点表达操作目标，禁用保留原因和可访问语义。危险操作统一含义和确认流程，各平台使用现有组件。空态、错误与加载分别处理，提示靠近相关操作。

自定义颜色需验收浅/深及提高对比度场景；既有 RGBA bridge 不代表自动具备所有系统颜色自适应能力。运行时主题解析继续由 ThemeProvider 和 CSS 负责；禁止增加平行的 Swift 主题解析器。

## 排版

统一正文、品牌、分组标题、辅助信息等文字角色。Web 保留用户字体选择与现有字号；原生保留系统字体，以现有 16/14/12pt 基准按对应 text style 缩放。不能将可移植基准解释为所有平台最终固定字号。

正文行高、笔记排版和编辑器 measure 继续由既有排版设置拥有，本次不改变。密集导航沿用单行截断，VoiceOver 提供完整标题或标签路径；大字号允许行高与内容区增长。

## 间距、尺寸、圆角

v1 提供 4/8/12/16/24/32 的已有间距基准及现有七档圆角。DTCG dimension 使用 CSS 逻辑 px 表达基准；CSS 圆角仍按 16px 基准输出 rem，原生显式映射到 pt。它们不是设备物理像素换算规则。

桌面紧凑侧栏默认行高 32px，触摸布局基准 48；保留现有大小变体。图标视觉框、触摸命中区、容器外边距分别建模。自定义原生展开控件常规命中目标为 44pt，这是产品策略，不能误写成所有系统控件的强制尺寸。

侧栏宽度按平台容器计算：Web 沿用响应式规则；原生使用 safe area 和系统 layout margins，不用固定设计稿宽度覆盖。断点沿用现有 768px 规则。

## 图标与材质

自定义侧栏使用同源 Lucide，随文字适度缩放，Emoji 保留用户配置。原生系统菜单与工具栏可继续使用 SF Symbols。图标按钮必须有可访问名称。系统材质、柔和滚动边缘、弹层形状保留平台行为；不为追求像素一致而重画系统组件。

## 动效与操作

保留现有过渡、推移、滚动、焦点恢复和 Reduce Motion 路径，不新增动效。Web 使用 Base UI 处理键盘、焦点和浮层组合。原生保留系统菜单、确认框、键盘及 UIKit 手势容器。按下、展开与导航互不串动作，关闭弹层后焦点返回合理位置。

## 验收

每个组件记录适用密度、平台映射、状态和输入方式。Web 使用 Storybook，SwiftUI/UIKit 使用原生 Preview；同名场景使用各平台独立基准。完整 App 验证桥接、键盘、安全区、滚动和手势。截图说明环境与已知限制，性能用例与真实帧率/耗电测量分开报告。
