# MemoCard bridge v1 — M0/M1 contract

Native requests: `{version:1,requestId,operation,params}`. Replies: `{ok:true,data}` or `{ok:false,error:{code,message,retryable}}`.
Swift core exposes `public actor VaultStore`, `init(localDataURL: URL) throws`, `open(url: URL, create: Bool) throws`, and `perform(operation: String, params: Data) throws -> Data`. The returned Data is JSON **data**, not the reply envelope. Public `VaultError` exposes `code`, `message`, `retryable`. Host wraps errors. Host/UI operations are separate from core operations.

Local Web adds an optional actor-internal binding: `open(url:create:binding: UUID = UUID())`, `perform(operation:params:expectedBinding: UUID? = nil)`, and `asset(relativePath:expectedBinding: UUID? = nil)`. NativeHost passes its vault-open generation to Web calls. Core validates it before dispatch without suspension; switching directories invalidates old requests even when restored vault copies share the same `vaultId`. Legacy native call sites may omit the argument.

M1 core: `getStatus {}`, `queryNotes {query?,tags?,from?,to?,limit?,cursor?,deleted?}`, `getNote {id}`, `saveNote {id,body,tags,baseHash: string|null}`, `listTags {}`, `saveDraft {id,body,tags,baseHash,relativePath?}`, `getDrafts {}`, `importAttachment {name,base64,noteId?}`. Draft `relativePath` is optional rendering context, never an authoritative save destination. Attachment result `{relativePath,markdownPath,notePath}`; the core resolves `noteId` to its current location and returns a Markdown path relative to that note's directory. The editor updates its rendering and draft context from returned `notePath`, including when the file moves during editing. Missing/new IDs use the default `notes/` directory. Unsupported image types are rejected before writing. Supported imports are PNG, JPEG, WebP, GIF, HEIC and HEIF.
Query is literal case-insensitive body substring, tags AND, createdAt descending then id ascending. `from` is inclusive and `to` is exclusive. Pages observe both the requested count limit and a 2 MiB encoded-note budget; one larger valid note may be returned alone. Always follow `nextCursor`, even when a page contains fewer than `limit` notes. Content hash is SHA256 of source bytes.
Host: `selectVault {create:boolean}` (create Mac only), `getEnvironment {}` (platform, phase, mcpEnabled), `setMCPEnabled {enabled:boolean}` (Mac; directory picker when enabling), `pickImage {noteId?}` (native picker; attachment result), `openExternal {url}`, `getAsset` handled by native scheme, not arbitrary filesystem reads.
`window.webkit.messageHandlers.memocard.postMessage(request)` returns Promise<reply>. Native events use `window.dispatchEvent(new CustomEvent('memocard:event',{detail:{type:'notesChanged'|'statusChanged',...}}))` with structured arguments, never source concatenation. Local UI scheme `memocard-ui://app/index.html`; attachment scheme `memocard-asset://vault/<relativePath>`; deep links `memocard://note/<id>?vault=<vaultId>`.

The UI registers `memocard:open-note` before calling host `uiReady {}`. Native queues cold-launch links until ready and verifies the selected vault. The event carries `{id}` only; it never supplies a filesystem path or a write operation.

Local Web uses the menu bar service's loopback HTTP server, with a one-use fragment token exchanged at `POST /api/session` for an HttpOnly SameSite=Strict cookie. `POST /api/bridge` carries the same bridge envelope; same-origin authenticated attachments use `/api/assets/<relativePath>`. Its operation allowlist covers core note/draft/image operations and host-advertised vault actions. Browser file selection and safe external links are handled in the browser; directory selection remains native. The menu bar service supports `selectVault`, `listVaults`, and `activateVault`, while Mac App-only MCP settings remain native. `memocard-service://open-web` asks the installed menu bar service to create a fresh authorized page; the Mac App compatibility entry `memocard://web` delegates to that same command and does not start another server. Neither accepts file paths or return URLs. See `docs/LOCAL_WEB.md` for lifetime, limits and recovery behavior. MCP TCP authorization and read-only operations remain separate.

M1 UI includes honest setup/empty state, draft+save, cards/search/preview, native image import, status and MCP toggle. No mock persistence or fake completed statistics/trash. M2/M3 operations stay unavailable until platform gate passes.

TCP request: `{version:1,requestId,token,instanceId,vaultId,operation,params}` serialized as one UTF-8 JSON line. Reply is `{requestId,...bridgeReply}` plus newline. Authenticate token, instanceId AND vaultId before any data. Read-only operations only: getStatus, queryNotes (deleted always false), getNote (reject deleted), listTags. Request frame maximum 8 MiB; response maximum 62 MiB to accommodate JSON escaping of a valid 8 MiB note. Oversized responses return `RESPONSE_TOO_LARGE`. Timeout 15 seconds. Bind only IPv4 127.0.0.1 on ephemeral port, no Bonjour. Configuration is exported outside vault/repositories, mode 0600.

MCP tools: get_status, search_notes, get_note, list_tags. Complete serialized tool results are capped at 8 MiB for compatibility with default SDK clients. Oversized single-note results return `RESPONSE_TOO_LARGE`, never truncated content. MCP stdout protocol only. Node adapter rereads connection config for each call, validates loopback host and port. Connection file supplied by `--connection-file /absolute/path`. M1 smoke verifies protocol against actual Mac App; fixtures never count as iCloud or iPhone acceptance.

## Obsidian-compatible folders (2026-09-29)

Manifest version 2 scans Markdown from the vault root; frontmatter is optional and user-owned. Note API IDs and creation timestamps come from device-local identity records, never required source properties. Version 1 retains its original rules. `resolveLink {target, sourcePath, wiki?}` returns `{kind:"note",id,path}` or `{kind:"image",path}`; ambiguous/missing links fail explicitly. This is a UI bridge operation, not an MCP write capability. Version 2 attachments may reside anywhere non-hidden inside the authorized root. See `docs/OBSIDIAN_COMPATIBILITY.md` for preservation, identity and concurrency boundaries.

Nested tags use `/` separators. `queryNotes.tags` matches each requested tag or its descendants (for example `work` includes `work/design`, but not `workshop`); multiple requested tags still use AND semantics. `listTags` includes implicit ancestors and counts distinct notes per ancestor, not the sum of child counts. This applies to both browser and Swift stores without rewriting tags in Markdown.

Page titles: `Note`, `saveNote` and recovery records accept optional `title:string`. Omission preserves the existing title; an empty string explicitly clears it. The title is stored as YAML `title`, independently of the Markdown body; body headings are never promoted or removed. New UI pages explicitly send `title:""` and create an empty file immediately. Clearing an existing page preserves its ID and path. Recovery matching includes title so an older body-identical save cannot discard a newer title edit. Searches include titles.
